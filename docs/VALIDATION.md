# 0.9.1 验证记录

## 已完成的离线验证

- `.toc` 加载的九个主插件模块及探针均通过 Lua 5.1 语法解析。
- 16 项纯模型测试、19 项集成测试，以及历史回放、生命周期与探针测试通过。
- 新增外部红色计时：验证掉层后欠数不变、未满层新增时外部记录 ID 和到期时间原样进入主框、新外部记录从完整持续时间开始、秒数递减、关闭秒数和清零显示。
- 回归覆盖：无关光环不加层，只选一个显示来源，间隔 100ms 的两次定向更新不丢失，同次应用不重复计数，未知来源刷新暂停预测，失同步后新的完整增益周期恢复。
- 覆盖同时到期、到期同刻触发、多层重载不捏造计时、单层同步、秘密值拒绝进入模型、声音独立开关、战斗中设置、非战士、原生初始化失败。
- 模拟器对未知方法报错并检查原生封闭后修改；但不是 WoW 引擎，不证明所有受保护操作合法。
- 浏览器预览使用真实 Lua 主题与预览快照，已目视检查深色背景的四种状态。浅色/复杂背景截图阶段工具超时，未完成目视验证。不是游戏实测截图。

## 事件依据与处理

新增实际证据：2026-10-14 保存的旧版实战记录。记录了 778 条公开施法事件，其中 445579 为零；旧探针源码确认它记录全部公开的玩家施法成功事件。主插件已移除对该事件的依赖。脱敏提取的 tests/fixtures/combat-history.lua 只保留时间戳、定向回调类型及公开层数，不包含账号或角色信息，也不使用原生控件显示状态。

历史回放含 274 次处刑者定向刷新、17 个公开层数核对点，全部匹配；同一时间戳先执行回调再比较公开快照，避免将一次事件分发中的中间状态当作差异。回放推进 30 Hz 的到期处理。该结果支持旧版时间队列模型，但不证明全部战斗状态、全部版本及每个独立到期时刻。

参考本地 Blizzard 界面源码镜像 Gethe/wow-ui-source，12.1.5 标签提交 b9be9379719047977fca4dba1bb1d9988e8840b3，以及 12.1.0 CustomAuraButton 源码。

| 观察 | 处理 | 证据边界 |
|---|---|---|
| OnUnitAuraAddedEvent | 不作为处刑者触发 | 源码对所有新增光环广播 |
| 已选处刑者条目的 TriggerAuraAppliedAlert | 新增周期的预测起点 | 只钩选中的一个来源；仍需实测时序 |
| 445579 的公开 UNIT_SPELLCAST_SUCCEEDED | 不用于主插件计时 | 历史战斗日志未出现该事件 |
| 已选处刑者条目的 OnUnitAuraUpdatedEvent | 先匹配 ±200ms 的预计掉层，否则预测新增或溢出 | 回放支持此定向模型；不能推广到普通光环刷新；时间相关性不是独立层数证明 |
| 已选条目的 OnUnitAuraRemovedEvent | 无条件重置，并作废待处理刷新 | 源码按对应 auraInstanceID 分发 |
| 脱战可读光环数据 | 无光环则清空；单层可重建；多层只校验 | 每个字段使用前检查秘密值；脱战本身不保证公开 |
| 原生 SetApplicationBar / SetApplicationCount | 显示真实总层数 | 不返回独立到期时间，也不读回显示状态 |

采用两版都支持的 maxApplications，不依赖 12.1.5 新增的 minApplications。布局修改延迟至脱战；运行期不修改已封闭的光环子控件。不读取其显示状态作为隐蔽事件渠道。

## 游戏内验收

1. 安装全部模块，战士登录、重载、切专精、进入/离开副本；检查 `/ew status`、Lua 错误和受保护操作警告。
2. 在冷却管理器追踪处刑者；分别显示图标、条、两者，验证只有一个事件来源，其他增益不增加预测层。
3. 开发验收需要核对单次触发、连续五层、满层继续触发、自然到期、同时到期、整体取消的原生层数和预测时间。诊断插件不是主插件依赖，也不要求使用者安装。
4. 已有日志公开持续时间为 18 秒；仍需覆盖其他天赋和当前版本。重点检查 200ms 到期匹配在高延迟、同刻新增与掉层下是否误判。
5. 分别验证真实层数 1–5 的原生裁剪、阈值 1–4 的 `! 取消 !`；声音使用预测阈值，必须额外比对，不能称为原生层数触发声音。
6. 在战斗中打开设置、改阈值与缩放、重载、进入战斗前拖动，确保无污染或禁止操作；脱战应用延迟布局。
7. 观察实际 UI 缩放、中文字体、明亮和复杂背景下的秒数、红条、边框、提醒，确保无遮挡、错位、闪烁。
8. 模拟漏事件或来源变化，确认出现 `?`、预测隐藏、真实层数保留，下一完整周期或公开单层能恢复。

完成以上客户端验证前，该包只能视为可安装的开发构建，不能标记“实战验收通过”或“零 bug”。

0.9.1 已有用户实战使用反馈，但上述分项记录仍需在对应客户端版本上补充；不得将部分实测推断为全部场景通过。
